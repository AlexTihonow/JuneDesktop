    Таблицы и оформление автор модуля

    Модуль приносит свои таблицы сам; SQL пишется руками, цвета берутся из палитры.

    Миграции

    Файлы в migrations/ применяются по порядку номеров при запуске. Центральной схемы в проекте нет: модуль приносит свои таблицы сам.

    CREATE TABLE tasks (
  id         TEXT PRIMARY KEY,
  author_id  TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  text       TEXT NOT NULL,
  due        TEXT NOT NULL DEFAULT '',
  who        TEXT NOT NULL DEFAULT '',
  done       INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL
);

    Нумерация — 001_init.sql, 002_….sql и дальше. Применённое не переписывают: изменение схемы — это новый файл, а не правка старого.

    Объектно-реляционного отображения в проекте нет, запросы пишутся руками. Так видно, что именно уходит в базу.

    Оформление

    styles.css модуля подключается вместе с ним. Цвета и отступы берутся из переменных палитры — своих цветов модуль не заводит, иначе смена палитры перестала бы работать целиком.

    .tasks-list li {
  display: flex; gap: var(--space-3); align-items: baseline;
  padding: var(--space-2) 0;
  border-bottom: 1px solid var(--c-border);
}

    Переменные, которыми можно пользоваться: цвета --c-bg, --c-surface, --c-border, --c-text, --c-text-muted, --c-accent; отступы --space-1…--space-8; шрифты --font-ui, --font-display, --font-mono.
